This round is markedly better evidenced than the first two: the reviewer built the
tree, ran the unit tests, and wrote focused probes rather than reasoning from the
source alone. Where a finding is marked Accepted below it has been reproduced

Five of the accepted findings are defects in work I did in this project's recent

Line 75:Done: Separate readable formatting from lossless serialization. **The worst finding in the report and the one to fix first.** format() is %.6g and value_of() feeds the mask cache key, so distinct parameters collide: reproduced here with blue.sigma=1.8000001 and 1.8000002, which produce one cached mask where there should be two. That is a silent wrong hit -- the second run is served the first sigma's mask -- and it is precisely the failure the cache was designed around. save_config has the same defect at rest: a measured rate writes as `3.6061e+06`, five figures. Keep %.6g for display; add a round-trip serializer (max_digits10, C locale) for identity and persistence, and version the encoding.
Line 98:Done: Build calibration identity from the actual calibration request. Not independently reproduced -- accepted on the structural argument, which is the mask cache's own: a key assembled from a hand-picked list of inputs is a list to forget something from, and this one omits seed, shortlist and reuse while hashing pixels without dimensions. The remedy differs from the mask cache's deliberately, since the two have different legitimate exclusions; the shared part is that the request should be resolved once and then both keyed and executed.
Line 125:Done: Replace the raw config-token search with an option-aware first pass. Reproduced: with a real config present, `dither --no-config --threshold mask --explain` reports blue.rate as measured -- the flag is ignored because the pre-scan starts at argv[2] -- where the same flag later correctly reports fallback. The pre-scan also cannot tell a flag from a value, so a filename of `--no-config` disables configuration. Fix by sharing arity, not by introducing the ArgCursor the first review rejected.
Line 149:Done: Give numeric and paired arguments one strict parsing contract. Reproduced both divergences: `--supersample 2.9` resolves to 2 while `--set supersample=2.9` resolves to 2.9 and rounds to 3, and `--mask-size 32x32garbage` is accepted as 32. This changes what input is accepted, so it lands as a documented fix rather than as cleanup, and needs its own entry in the option reference.
Line 172:Done: Validate threshold names once before either execution path. Reproduced: `--threshold not-a-rule --explain` exits 0, and a real run prints `threshold=not-a-rule` in its summary before anything refuses it. The parser already validates generator and spacing names; the threshold is the one that was missed.
Line 186:Done: Separate cache writing from eviction and make failures truly optional. The split is worth having on its own, but the error-handling points are the substance: cv::imwrite and cv::imread can throw, so an optional cache must not be able to abort a valid main output; eviction subtracts a file's size even when its removal failed; hash_file cannot distinguish a short read from EOF; and build_identity overwrites file_size's error code with last_write_time's. The stale-.tmp comment promises a cleanup the code never performs -- that one is mine.
Line 214:Done: Give the config loader/writer explicit failure boundaries. load_config claims corrupt lines are ignored, but a registered number outside its range throws from set() -- so a cache file that is merely stale, which is exactly what a range change makes it, is fatal rather than skipped. save_config truncating in place is the other half: an interrupted write leaves no config rather than the old one. Write-and-rename, and validate at the read boundary.
Line 234:Done: Reuse to_logp in fit_expert; the old uncertainty is now checkable. Previously rejected for want of arithmetic identity, and the reviewer supplies exactly that -- 50 tables across Qc=2..32 including all-zero, matching exactly, with MI after to_logp also matching. That is new evidence and it reverses the earlier decision. Landing it still requires whole-mask byte-identity here, since table equivalence is not a program regression test.
Line 258:Done: Remove redundant Markov parameters and forwarding layers. report_occupancy ignores radius, report_weights ignores weights, gibbs_field takes an N that is always H*W, and markov's prepare_sample forwards unchanged to maskutil's. Note the correct exclusion the reviewer drew: inpaint's same-named helper also rank-flattens and must stay.
Line 281:Done: Compute the reference clumping profile once per calibration. 120 reference FFTs where 5 suffice, because clump_distance recomputes the reference's five level-set measurements on every draw. The constraint is that the selected temperature must not move: same distances, same order of reduction, serial and parallel alike.
Line 296:Done: Keep a calibration score with its temperature and winning index. Rediscovering the winner by floating-point equality against `best` is fragile in a way that costs nothing to remove. The interpolation point is the sharper one: it assumes ts[1]-ts[0] spacing that failed draws can invalidate.
Line 313:Done: Give the direct mask one owned working field. Three image-sized clones where one is needed, and the ownership boundary is currently invisible. Behaviour-preserving, and the reviewer correctly separates it from the two-sorts question, which is not a reason to touch random tie-breaking.
Line 330:Done: Validate overlap against tile dimensions before quilt_axis. Reproduced: `--mask-size 16x16 --set direct.overlap=32` aborts on `keep > overlap` inside maskutil, with an OpenCV assertion in place of a diagnostic. Both values are inside their registered ranges, so the ranges cannot express the relationship and the geometry has to be resolved before the crop.
Line 350:Done: Validate each inpaint level before allocating and querying it. Reproduced, though not as predicted: `--mask-size 16x16 --set inpaint.levels=5 --set inpaint.radius=3` aborts inside cvflann on `result.full()` rather than reading out of bounds. Same class and same fix -- validate the coarse dimensions at the top of the level loop -- and the reviewer was explicit that the path was found statically, which is why the observed failure differs.
Line 372:Done: Do not construct a cache key when caching is disabled. Under --no-config the key is still built, which reads and hashes the whole sample file to produce something nothing consumes. Cheap to gate and it makes the disabled path honestly disabled.
