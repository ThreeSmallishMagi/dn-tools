Highest Priority
----------------

P1 - `spatial_floydsteinberg()` still drops residual on the final row.

  File: dither.cpp:252

  The denominator still counts every tap with a valid column:

    if (0 <= t.c && t.c < W) total += t.w;

  but the deposit only happens when the row is valid too:

    if (t.r < H && 0 <= t.c && t.c < W)

  On the last row, the below-row taps are counted in `total` and then skipped, so
  residual is silently lost. The clean fix is also shorter: define one predicate
  and use it in both loops.

    auto valid = [&](const Tap& t) {
        return 0 <= t.r && t.r < H && 0 <= t.c && t.c < W;
    };

  Then sum and deposit only valid taps.

P1 - `maskutil::rank_order()` silently assumes continuous `CV_32F` input.

  File: maskutil.cpp:11

  `rank_order()` flattens with `const float* v = f.ptr<float>()` and indexes as
  if the matrix has no row stride. Current callers mostly pass freshly allocated
  Mats, but this is now a shared utility and the signature does not document or
  enforce that contract. A future ROI/non-contiguous Mat would rank the wrong
  memory.

  Either:

    - add `CV_Assert(f.type() == CV_32F && f.isContinuous())`, or
    - make the helper stride-safe by comparing through `(idx / cols, idx % cols)`.

  If performance matters, the assert is enough for this codebase's current usage.


Cross-Cutting Improvements
--------------------------

P2 - Define one helper for padded toroidal Gaussian blur.

  Files: spectralmask.cpp:41, markov.cpp:448

  `smooth_power()` and `highpass_field()` both implement "wrap pad, Gaussian
  blur, crop back". The data and post-processing differ, but the border policy is
  the same hard-won rule. A `maskutil::toroidal_gaussian_blur()` helper would make
  the behavior consistent and reduce repeated OpenCV boilerplate.

P2 - Move shared frequency helpers into `maskutil`.

  Files: spectralmask.cpp:31, markov.cpp:824

  `spectralmask.cpp` has `bin_freq()`, while Markov calibration computes the same
  signed DFT bin frequency inline in `level_set_low()`. A shared
  `maskutil::bin_freq(i, n)` would make the calibration and spectral code agree
  by construction.

P2 - Add a tiny range builder for parameter registration.

  Files:
    dither.cpp:111
    bluenoise.cpp:163
    spectralmask.cpp:185
    markov.cpp:1130
    inpaint.cpp:260

  `params::add_const()` helped, but calls still carry noisy `{{lo, hi}}` and
  `(long long)` casts. A helper like `params::range(lo, hi)` plus overloads
  `add_const_i`, `add_const_d`, and `add_const_s` would make registration blocks
  more data-like and avoid the blank-line artifacts visible in several files.

P2 - Use one complete-number parser.

  Files: dither.cpp:570, dither.cpp:661, defaults.cpp:457

  CLI numeric parsing, `--set` numeric parsing, and config parsing each do the
  same `stod` plus "all characters consumed" dance. A small helper such as
  `parse_complete_double()` and `parse_complete_integer()` would reduce repeated
  exception handling and keep error behavior aligned.

P3 - Keep all private helper linkage consistent.

  Files: bluenoise.cpp:19, inpaint.cpp:155, markov.cpp:800

  Some files use an anonymous namespace, some use `static`, and `markov.cpp`
  currently leaves several helper functions with external linkage. Pick one
  convention per file; anonymous namespaces read best for these implementation
  helpers.

  `rank_uniform_unit()` and `rank_uniform_signed()` only differ in the formula

  File: maskutil.cpp:38

  Since this is now the common threshold-mask exit path, add a debug assertion
  that `order.size() == sz.area()`. Optional: assert each index is inside range
  when debugging. That catches generator bugs at the boundary where they become
  corrupted images.

P2 - Name the high-pass sigma constant.

  File: maskutil.cpp:53

  The `0.1874` half-power conversion also appears in spectral and Markov-related
  comments. A `constexpr double kHalfPowerSigmaPerPixel = 0.1874;` in `maskutil`
  would make the convention searchable.

P3 - Consider offering `rank_bins()` here too.

  File: markov.cpp:97

  Markov's `rank_bins()` is still local because it maps ranks to quantization
  bins rather than a uniform float field. It is general enough to live beside the
  other rank helpers if another generator or test starts needing it.


bluenoise.cpp
-------------

  Files: bluenoise.cpp:19, bluenoise.cpp:52

  Most helper functions are `static`, but the file-scope types still sit in the
  global namespace. An anonymous namespace around the implementation helpers

P2 - Track rank order directly instead of storing a rank matrix.

  Files: bluenoise.cpp:80, bluenoise.cpp:126, bluenoise.cpp:140

  index into `std::vector<int> order` as it goes, then return

  the final nested scan over it.

  Files: bluenoise.cpp:111, bluenoise.cpp:130

    seed_heap_with_empty_pixels()
    push_updated_empty_neighbors()

  The current code is correct, but the loop still mixes policy with heap
  maintenance.

P3 - Normalize style in `makeSparseGaussian()`.

  File: bluenoise.cpp:25

  The rest of the project mostly uses spaced operators and multi-line simple
  loops. This function still has compact expressions like `mul*sigma`,
  `dy=-radius`, and `for (auto& t: kernel)`. A light formatting pass would make
  it match nearby code.

P3 - Remove blank-line artifacts in the registration block.

  Files: bluenoise.cpp:179, bluenoise.cpp:185
